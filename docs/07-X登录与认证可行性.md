## 3. A：Snail 自身登录

推荐单人 MVP 使用 Cloudflare Access 保护 Vite 应用与用户 API，Worker 核验 `Cf-Access-Jwt-Assertion` 的签名、issuer、应用 audience、过期时间，并从已验证身份映射资料库；不能只信任邮箱头或客户端传来的 library ID。[70][71]

Access 支持通用 OIDC；若未来需要面向公众的产品账号，可以另接合适的 OIDC 身份提供方，X 授权仍作为“连接来源账号”的独立流程。[72][58]

Access 有全局、策略和应用会话时长及撤销机制；文档默认全局时长为 24 小时，实际策略可不同，不与 X Web cookie 或 X OAuth 的时长混用。[73]

本项目设计：用户网页走 Access；Connector 走独立的、严格限权的设备接口，设备凭据只允许向已配对资料库发送数据和查询自己的任务。设备接口不依赖定时弹出 Access 登录页，也不能因单独鉴权而暴露整个用户 API。配对须由已登录 Snail 的用户批准，详见 08。

尚未部署 Access、测试真实 JWT 或选择实际 IdP。因此 A 的 GO 是平台能力与架构判断，不是本机已有一个可用 Snail 登录系统。

## 4. C：本机已登录会话的授权、保存与失效

### 一次授权分成两件事

1. **X 会话**：用户在自己的 Chrome 正常登录，MFA/验证码由用户在官方界面处理；Connector 不收集密码、不自动登录或解锁。
2. **Snail 设备配对**：用户在 Snail 确认这台本机及资料库，授予“读取我的书签并发送元数据”范围；保存文件另受具体任务的权利与容量检查。

OpenCLI 的 Browser Bridge 借 Chrome 扩展与本机 daemon 执行页面读取；`auth_token` 与 `ct0` 的存在是 quick check，`bookmarks` 则通过页面内带现有会话的 GraphQL 请求取得数据，后者才是本次更强的认证证据。[80][81]

| 材料 | 生命周期与保管设计 | 撤销 / 失效处理 |
| --- | --- | --- |
| X Web 会话 cookie | 保持由 Chrome 管理，不另做云端 cookie 仓库；不假定固定有效期 | X 退出、风控或会话失效后进入 `needs_user_auth`，用户正常重登 |
| `ct0` / `X-Csrf-Token` | 仅在当前本机 adapter 请求内使用；不写任务、日志或配置 | 每次按当前会话取得，不把旧值长期缓存 |
| Web 客户端 `Authorization` | 源码客户端材料；不等于用户授予 Snail 的 OAuth token，也不能独自读取私人书签 | 固定适配器版本；请求被拒绝即停止，不能轮换身份绕过 |
| Snail 设备凭据 | 随机高熵值放操作系统钥匙串；云端仅存摘要、范围、过期及撤销状态 | 用户可单独撤销该设备；不会自动把 X 全账号登出 |
| 本地书签游标 / 待发送内容 | 属于私有数据；限定目录权限、最少字段，敏感内容加密；不进诊断包 | 用户断开时清除游标和本地待发送数据，保留可选择删除云端副本的入口 |

前两项 cookie 的取用与第三项头的来源是已读源码事实；存储、设备 TTL 和状态处理是 Snail 设计，未部署。[80][82]

**不把 X cookie 放 Worker/R2/D1：**Web cookie 没有 `bookmark.read` 这种对 Snail 可执行的细粒度授权，现有 OpenCLI 会话可供多种读写适配器使用；把整套会话复制到云端扩大了账号权限和泄露影响。[80] 因此本设计禁止这种传输，即使加密 D1/R2，也不改变权限过宽、难以只撤销 Snail、需要复制与恢复会话的问题；这是架构取舍，不是声称这些产品不能储存加密字节。

Chrome 当前文档建议敏感用户数据使用 `storage.session`，并说明它保存在内存、浏览器重启等情况下会清除。[84] 本设计不把 `storage.local/sync` 当作秘密保险库；持久的 Snail 设备凭据建议放本机钥匙串，X cookie 继续留在浏览器正常会话，不让用户手工粘贴 cookie。

已读安装版本的默认 `Page.goto` 会注入 stealth 补丁；首次按用户指定执行原版 CLI 时未改动此默认行为，发现后，后续真实分页/文件夹观察器明确使用 `waitUntil: 'none'`，跳过该注入，仍取得 Bookmarks 200。[80][81][82] 没有对 challenge 做求解或重试；未来 Connector 必须使用这一不注入指纹补丁的路径，不能直接照搬通用 CLI 启动链。

## 5. B：未来纯云端的官方 OAuth 路径

### 5.1 当前官方契约与最小 scopes

`GET /2/users/{id}/bookmarks` 读取已授权用户自己的书签；先用 `/2/users/me` 得到用户 ID，再绑定 `{id}`，不能让前端填写任意账号后声称有权读取。[61][65][77]

| Scope | 本研究的选择 | 原因 |
| --- | --- | --- |
| `bookmark.read` | 必需 | Bookmarks 读取。[61][65] |
| `tweet.read` | 必需 | 帖子读取；官方说明其范围可能包含用户可见的受保护帖子，Snail 仍不复制这些内容。[59][61][65] |
| `users.read` | 必需 | 当前用户与相关用户信息。[61][65] |
| `offline.access` | 后台同步必需 | 官方仅在请求此 scope 时发 refresh token。[59][60] |
| bookmark/tweet/like/follows 写权限、DM、邮箱、`media.write` | 不申请 | 不需要修改 X、读取私信或上传媒体；`media.write` 是上传权限，不是下载许可。[59][65] |

推荐 Worker 作为 confidential Web App 后端：由 Worker 生成随机 `state`、43–128 字符范围内的 PKCE verifier，使用 S256 challenge；前端只跳转授权页，不保存 client secret 或 X token。[59][60][74][75]

### 5.2 授权码、token、刷新、撤销

| 环节 | 官方事实 | Snail 处理 |
| --- | --- | --- |
| 浏览器授权 | 指南入口为 `https://x.com/i/oauth2/authorize`；传 response_type、client_id、redirect_uri、scope、state、code_challenge、S256。[59][60] | redirect URI 精确注册；仅允许固定本应用回调，不接受任意 return URL |
| 换 token | `POST https://api.x.com/2/oauth2/token`，form body；包含 code、grant_type、redirect_uri、code_verifier；public client 需要 client_id，confidential client 使用客户端 Basic 认证。[60] | 客户端认证只发给固定 token origin，不跟随跨域重定向 |
| 授权码时限 | 指南写明需在 30 秒内换取 token。[59] | 回调先校验 state 与 Snail 会话绑定，立即交换；不要先排长队或插入第二次人工登录 |
| Access token | 文档给出的默认时长为 2 小时；`offline.access` 提供刷新能力。[59] | 以响应 `expires_in` 为准，提前少量刷新；不能将 refresh 能力解释成 access token 永不过期 |
| Refresh | 同一 token endpoint，grant_type=refresh_token；无需用户再次交互，前提是刷新凭据仍有效。[59][60] | 按连接建立持久化租约，原子替换返回的新 token/version；若返回新 refresh token，保存新值 |
| Refresh 的长期有效性 | 已读官方页未给出可据此保证的固定 refresh TTL、永续性或所有 rotation 行为。[59][60] | 不写“永不过期”或凭记忆写“六个月”；`invalid_grant`/撤销转重授权，禁止循环重试 |
| 撤销 | `POST https://api.x.com/2/oauth2/revoke` 可撤销 access/refresh token；用户也可在 X 的 connected apps 页面撤销。[60] | 删除本地连接秘密、取消任务、清除刷新租约；不能仅删除 UI 图标 |

OAuth tokens 可由 Worker 正常 HTTPS 使用；存储建议是 client secret 放 Worker secret binding，用户 token 用应用密钥进行 AES-GCM 加密后放 D1，并将 library/connection/version 绑定为 AAD，密钥版本独立管理。[21][59][60] 这里允许的是**有 scopes、可撤销的官方 OAuth 凭据**，不是 C 的整套 X Web cookie；R2 不做凭据存储。

单 isolate 内存锁不能解决多个 Worker/Queue 实例的刷新竞争；设计使用 D1 条件更新的 connection lease/version，刷新结果晚到、设备被撤销或账号已切换时拒绝覆盖。该分布式一致性尚未实测。

### 5.3 Bookmarks、媒体与套餐

当前 OpenAPI 的 Bookmarks 页大小为 1–100，并提供 `pagination_token`；媒体可使用 `attachments.media_keys` expansion 和 `media.fields=type,url,variants,preview_image_url,duration_ms,width,height`，在 `includes.media` 关联结果，字段存在仍须逐帖核验。[62][65][10]

当前限额页列 Bookmarks GET 每用户 180 次/15 分钟；folder GET 为 50 次/15 分钟，不能将此数字套用于 OpenCLI 的内部 Web GraphQL，也不能将限额表“Per App”一列当作 app-only 授权证明。[69][65]

当前价格页是按用量预付 credits，不应继续套旧 Free/Basic/Pro 月费表；普通 Post Read 为 $0.005/资源，User Read 为 $0.010/资源。[11] **Owned Reads 明列 `/2/users/{id}/bookmarks` 为 $0.001/资源，但条件是授权用户同时是该 developer app 的所有者**，不能自动推广到所有 Snail 用户。[11] 24 小时 UTC 去重收费是 soft guarantee，余额不足可停止 API 访问；具体 app 的启用权限、expansion 账单和文件夹收费应由一次真实请求与控制台记录确认。[11]

“能登录 X”“拥有 X 订阅”“已经配对 OpenCLI”均未证明 developer app 已获 Bookmarks API 访问；本研究没有购买 API credits，也没有真实 OAuth grant。[81]

### 5.4 没有已核实的书签事件推送

已检查当前 X Activity introduction、payloads、Account Activity 事件表，以及 OpenAPI 的 `CreateActivitySubscriptionRequest.event_type` 枚举；没有发现可用的 bookmark create/delete 事件契约。[65][66][67][68] Payload 中的 `bookmark_count` 是帖子的统计字段，不能替代“我新增了哪个书签”的事件。[67]

因此推荐**轮询 Bookmarks 并去重**，不设计依赖 bookmark webhook 的关键链路。即使未来出现事件，事件也只触发授权下的帖子/媒体解析，不携带版权许可或保证返回原始视频文件。[10][12][13]

### 5.5 官方文档不一致，不能用猜测填平

- PKCE 指南使用 `x.com/i/oauth2/authorize`，OpenAPI security scheme 写 `api.x.com/2/oauth2/authorize`；真实应用实验先按交互指南配置并记录最终行为，不将 schema URL 差异隐去。[59][60][65]
- 老 authentication mapping 的 Bookmarks 行有路径笔误且只标 OAuth 2；当前 OpenAPI GET 还列 OAuth 1 UserToken。此次只推荐证据一致的 OAuth 2 scopes 路径，没有验证 OAuth 1 可用性。[76][65]
- Bookmarks integration 页此次返回的正文在 “These specific endpoints require the” 处结束；不能据残缺页面判断授权要求。[78] 使用专门 quickstart、完整 OpenAPI 交叉核对。[61][65]
- 现有文档的每页上限并不证明无限历史可取；没有把旧资料常见的总量数字或“Get all”文案当全历史完成保证。[62][65][77]

## 6. D：无登录路径的可用边界

02 已记录给定公开页与 oEmbed 200、三个 MP4 档位、完整下载及 Range 成功；裸 syndication 则是 200 和 `{}`。[56] 这说明**这个时间、这个网络、这条公开链接**可读，不说明它能枚举私人 Bookmarks 或替代用户授权。[56][77]

新增匿名检查均为真实 HTTP：`/2/users/me` 与官方文档示例 ID 的 `/2/users/{id}/bookmarks` 都返回 401、`application/problem+json`、99 字节；SHA-256 均为 `8f20ff0c6196b3d88227a60b7b32325bae08a23c17051edb358c5e321540d76f`。[81] 后者使用公开文档示例 ID，不是本机账号身份，也未取得其书签。[61][81]

HTML/schema 改动、删除、区域/账号限制、云端出口差异、登录墙或 challenge 都是边界；遇到访问控制失败就停止，不把 token 生成、账号轮换、验证码求解或指纹伪装作为降级策略。平台对自动访问的许可也必须满足，换成本机并不会自动改变条款。[12][13]

## 7. 纯 Worker 能承担哪些认证与媒体环节

| 环节 | 判断 |
| --- | --- |
| Snail Access JWT 校验 / 通用 OIDC 回调 | Worker 可实现；真实部署、IdP 配置未测。[70][71][72] |
| 官方 X OAuth 回调、PKCE、token 交换、刷新、撤销 | HTTPS＋Web Crypto 可承载；本轮只做无秘密 contract，没有实际 X token。[21][59][60][83] |
| 官方 Bookmarks 轮询及 JSON 解析 | 有官方接口；应用账号授权/套餐仍需 B 实测。[61][65] |
| 接收 Connector 的规范化元数据 | 推荐；Worker 自行做资料库、幂等、schema、来源与 SSRF 校验，不能因“本机发送”而信任 URL |
| 获准 MP4 / 封面流式写 R2 | 本机 workerd 的真实 CDN 请求已成功；实际云端 R2、出口与大文件仍待验收。[56][82] |
| 使用当前 Chrome 登录会话 / 运行 OpenCLI | 必须留在用户本机；普通 JS Worker 没有 Chrome profile 或可用系统子进程。[22][80] |
| challenge、MFA、网页登录过期 | 必须由用户在官方浏览器页面正常处理；不建设自动绕过路径 |
| 仅有获准 HLS、转封装/抽帧等 | 需要时增加本机受限 extractor/ffmpeg 进程；本例直接 MP4 不需要合流。[38][39][56][82] |

## 8. 无秘密的 PKCE / 状态机最小 spike

临时文件 `runtime/auth-contract.mjs` 与 `runtime/run-auth-contract.mjs` 在本机 workerd 执行，**17/17 通过**；响应 200、`application/json`、1,250 字节、SHA-256 `268859af333fffe003958f6254b924809f531932485efce1ac8d752f575f91df`。[83]

覆盖 RFC 7636 S256 公共测试向量、最小 scopes、正确回调、未知/错会话/过期/重放 state、拒绝授权、错误 PKCE、缺 scope、X 账号绑定冲突、同 isolate 并发刷新、模拟 invalid_grant、刷新中撤销、AES-GCM AAD 隔离、设备凭据摘要和批次冲突。[83]

这些结果验证的是临时契约和运行时密码学能力；**没有**测试真实 X OAuth、Cloudflare Access JWT、跨 isolate D1 锁或线上秘密存储。[83] mock 中的 2 小时、身份与 token 都是合成输入，不涉及用户真实秘密。

可在证据目录仍存在时复跑：

```sh
cd /tmp/snail-research-iKKC3rYb/runtime
node run-auth-contract.mjs
```

其他命令及源码摘要见 08；本轮不在仓库创建脚本或产品实现。

## 9. 必须先通过的端到端实验与停止条件

以下是**后续验收计划**。没有执行真实账号撤销、X 写操作、云端部署或充值。

| Gate | 最小实验 | 通过条件 | 不通过时 |
| --- | --- | --- | --- |
| G1 本机可靠认证 | 专用正常 Chrome profile；不注入 stealth；重启/休眠恢复后再读两个分页，跨 7 天低频复测 | 同一已授权账号、无 challenge 自动处理、断页不报全量成功、秘密不出本机 | 停止后台同步；保留用户主动扩展发送 |
| G2 真实云端接力 | 选择用户自有或已许可视频；Connector→配对 API→Worker→真实私有 R2→登录用户播放 | 哈希/大小相同，206/416 正确；未授权用户/设备不可读；无 X cookie 出网到 Snail | 使用本机下载后普通上传；不可声称纯 Worker 全链通过 |
| G3 生命周期与权限 | 在隔离测试配置中撤销 Snail 设备、模拟过期；用户以后自行执行 X 正常退出/重登 | 撤销立即停止提交，旧任务不能发布；换账号必须重新确认绑定 | 不开放定时无人值守 |
| G4 轮询完整性 | 用户以后手工收藏/取消一条自己有权测试的帖子；重复 poll、进程中断、429/游标失效 fixture | 新增只入库一次；旧帖新收藏不漏；未完成扫描不推断删除 | 限定为“最近 N 条同步”，明确窗口，不宣称全历史 |
| G5 合法保存 | 确认平台访问依据和具体视频 own/license/permission；验证来源删除/撤回处理 | 保存、用途、保留时限符合授权；未知权利只保留允许的链接 | 只提供上传和来源链接，不自动复制视频 |
| G6 官方纯云端（可选） | 已批准 developer app＋最小 scopes＋一次人工授权；身份→分页→媒体→刷新→撤销 | Bookmarks 200、实际权限与账单可承受，过期后刷新有效，撤销后旧凭据不可继续用 | B=NO-GO；保留 C，不能改用云端 cookie |

### 官方授权最小人工步骤，不索取凭据

1. 用户以后在 X Developer Console 建立/选择自己的合规 App，启用 OAuth 2、Web App、精确 HTTPS 回调；确认 Bookmarks 可用和费用上限。
2. 配置人员通过受控 secret 管理界面放入 client secret；不发到聊天、不粘贴进 Vite、不写 shell 历史。若尚未有部署入口，先完成安全回调原型而非让用户提供秘密。
3. 用户在已登录 Snail 页面点“连接 X”，检查只申请 `bookmark.read tweet.read users.read offline.access`，在 X 官方页面确认；MFA 仅在官方页面完成。
4. Worker 自动交换 code、调用 `/2/users/me`、读取一页 Bookmarks；先展示账号确认与统计，再根据用户允许的窗口分页，不默认下载整库视频。
5. 选择自己的授权视频做文件实验；记录状态、MIME、字节和摘要，不记录请求认证头、授权码或原始私人响应。
6. 后续跨过 `expires_in` 检查刷新；用户主动撤销这个测试 App，再验证停止。新增/删除书签测试由用户自己操作，本轮没有执行。

风险是授权范围包含账号可见的帖子与私密书签信息、后台 refresh 凭据持续有效期间的读取能力、API 计费以及内容权利；Snail 只接收功能所需信息并提供断开/删除入口。[59][60][11][12]

### 后续验收脚本契约

下面在**完成相应 API 后**于已登录 Snail 的同源浏览器环境运行；当前没有这些产品接口，不能把这段脚本当本轮真实 OAuth 成功证据。接口返回必须是脱敏诊断投影，不能包含账号身份、token 或原始书签。

```js
// 仅同源 Snail 会话；脚本不索取或输出 X 凭据。
const read = async path => {
  const r = await fetch(path, { credentials: 'same-origin', cache: 'no-store' });
  if (!r.ok) throw new Error(`验收接口失败：${r.status}`);
  return r.json();
};
const c = await read('/api/connections/x/acceptance');
console.assert(c.identity_bound === true, '必须绑定经过验证的账号');
console.assert(c.scopes_ok === true, '必须满足最小读取 scopes');
console.assert(c.bookmarks_http_status === 200, '必须实际读到 Bookmarks');
console.assert(c.pagination_verified === true, '必须观察非空 cursor 的下一页');
console.assert(c.refresh_after_expiry_verified === true, '需真实跨过 token 过期点');
console.assert(c.secrets_in_diagnostics === false, '诊断不能含凭据');
console.log({
  bookmarks: c.bookmarks_http_status,
  media_status: c.approved_media_http_status,
  range_status: c.approved_media_range_status,
  hash_match: c.r2_hash_match,
});
// 用户另行撤销测试授权后再次检查：status=revoked/needs_user_auth，后台提交=0。
```

认证研究结论不再是“本机路径未知”：有限窗口的真实账号读取已经成立。剩下的关键工作是把这条路径限制为安全、可撤销、可恢复的 Connector，并满足 G1–G5；未经这些验收，不以整理、搜索或低存储费用掩盖认证问题。
