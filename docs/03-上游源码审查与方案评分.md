## 3. 逐个候选的源码发现

### 3.1 OpenCLI：适合本机浏览器桥，不是纯 Worker 下载库

`package.json` 声明 Apache-2.0、Node `>=20.18.1`，依赖包括 `ws`、`undici` 等；X 适配器文档要求正在运行且已登录的 Chrome 和 Browser Bridge 扩展。[37]

| 已检查位置 | 实际机制 / 对本项目的影响 |
| --- | --- |
| `clis/twitter/download.js:306` 附近 | 注册 COOKIE 策略，支持 profile 媒体及单帖 URL；产品只考虑单帖，不暴露 profile 批量抓取。[37] |
| `clis/twitter/download.js:425–470` | 单帖路径访问页面，从 DOM 收集图片、video 和 videoPlayer，再读浏览器 cookie 交给下载辅助函数。[37] |
| `clis/twitter/download.js:349–418` | profile 路径复用内部 GraphQL 元数据和分页；不是官方 `/2/tweets` 接口。[37] |
| `clis/twitter/auth.js` | 检查会话 cookie 和用户身份；本次未执行。[37] |
| `src/download/media-download.ts:90–150` | 对部分视频类型导出临时 Netscape cookie 文件，再选择 HTTP 或 yt-dlp 下载。[37] |
| `src/download/index.ts:280–316` | 通过 `node:child_process` 启动 yt-dlp；未给 cookie 文件时还可能自动尝试 Chrome cookie。[37] |

单帖 DOM 选择器扫描页面上的 video/videoPlayer，snail 若复用这个思路必须再次按目标 post ID 收窄，避免把回复区视频导入。浏览器里的 `blob:` 地址也不能直接交给服务端下载；这一点需要在真实会话测试中检查，不把本次源码审查当作已经修复。

**采用建议：**本机浏览器桥现已成为主要认证采集候选；交给云端的是受校验的媒体描述或媒体字节，不传浏览器 cookie。安装版本的 Bookmarks 分页已实测；DOM download 范围错误与伪 MP4 已发生，必须从 Connector 白名单中排除。[81][82] 不把原版 daemon 暴露为公网下载 API。

### 3.2 yt-dlp：优先的通用辅助进程候选

项目源码和 PyPI 源码/轮子以 Unlicense 发布；部分打包发行物包含其他许可证代码，PyInstaller 合并发行物的许可证不同，不能只看仓库的 LICENSE 就替二进制分发作结论。[38]

`pyproject.toml` 要求 Python 3.10+，基础依赖列表为空；README 推荐 ffmpeg、ffprobe 和 JavaScript 运行环境等可选依赖，其中音视频合流需要 ffmpeg，完整 YouTube 支持的额外依赖不等于本例 X MP4 下载也必须安装。[38]

| 已检查位置 | 发现 |
| --- | --- |
| `yt_dlp/extractor/twitter.py:100–153` | 默认选择 GraphQL；区分登录和 guest 请求路径，不能称为单纯抓取公开 HTML。[38] |
| 同文件 `1156–1206` | 支持 syndication；构造客户端参数并使用特定 User-Agent；源码还提醒可能缺失媒体/元数据。[38] |
| 同文件 `1239–1273` | 从 `video_info.variants` 构建格式与封面；默认排序可偏好 HLS。[38] |
| 同文件 `1340–1371` | 处理多媒体项与指定视频索引，需要防止自动带入引用帖。[38] |
| `README.md`、`THIRD_PARTY_LICENSES.txt` | 依赖与发行物许可需要分别核对。[38] |

本次强制通用 HTML extractor 对示例返回 `Unsupported URL`；没有测试上述专用 API 路径，因此没有“yt-dlp 默认命令成功下载本例”的证据。[56]

**采用建议：**混合架构中作为固定版本、受限输入的独立进程；先选兼容的单文件 MP4，只有获得允许且确实需要时才用 HLS 合流。禁止自动读取浏览器 cookie、使用未知插件、任意命令参数和自动更新。

### 3.3 gallery-dl：图片/整组媒体更合适，MVP 无需并存两套下载器

`setup.py` 声明 GPL-2.0-only、Python 3.8+、`requests>=2.11.0`；`gallery_dl/extractor/twitter.py` 读取 `video_info.variants`，默认以 bitrate 选择视频，也可以把任务交给 ytdl 路径。[39]

该 Twitter extractor 检查会话 cookie；用户名/密码登录实现明确提示已经不支持，应使用浏览器 cookie，内部请求还涉及 CSRF 与 transaction ID 逻辑。[39]

**采用建议：**如果后续产品转向图片和整组素材再考虑。当前“视频优先”已经有 yt-dlp 候选，不为覆盖相同功能同时维护 gallery-dl；若重新分发程序或修改版，要落实 GPL 对应义务，进程隔离本身不是许可证豁免。[39]

### 3.4 Twikit：可以取得媒体，但直接下载实现不适合大文件 Worker

Twikit 使用 MIT 许可证，要求 Python 3.8+，依赖包括 httpx、lxml、BeautifulSoup、pyotp、m3u8 和 Js2Py-3.13；`get_tweet_by_id` 通过内部客户端请求获取帖子。[40]

`twikit/media.py:98–107` 与 `155–181` 的下载路径先取 `response.content`，然后写文件，是整响应缓冲；`client/client.py` 还包含会话持久化、transaction ID 及可选账号解锁/验证码求解接口。[40]

**采用建议：**本项目不采用；不运行其账号解锁或求解器。即使只借鉴字段模型，也需另写有界流式下载和权限边界，不能把“无需 API key”解读为“无需账号或平台授权”。

### 3.5 twitter-api-client：历史实现参考，不作为新产品依赖

项目使用 MIT 许可证；依赖包含 httpx、aiofiles、orjson、m3u8、uvloop 等，README 提醒用户名/密码登录不稳定并建议 cookie，会话缺失时只有有限 guest 能力。[41]

`twitter/scraper.py:248–329` 的 `download_media` 会选择高码率变体并流式写本地文件，但创建下载客户端时包含 `verify=False` 和默认高并发参数；该源码路径不能直接作为安全默认值使用。[41]

**采用建议：**不采用。理由是近期代码证据不足、依赖范围较大、TLS 校验默认值需要修正；这些是本次审查的具体发现，不是对所有历史版本的概括。

## 4. 官方接口、公开页面与浏览器路径比较

| 路径 | 元数据 | 视频变体/下载地址 | 纯 Worker | 本次实测 | 主要边界 |
| --- | --- | --- | --- | --- | --- |
| X 官方 API | 结构化字段、附件扩展。[9][10] | 支持 variants 字段。[10] | HTTPS/JSON 可行；需凭据 | 匿名 401。[56] | 应用访问权限、费用、存储与展示条件 |
| oEmbed | 作者、来源、嵌入 HTML。[8] | 不承诺返回独立 MP4 清单 | 可行 | 200，无 variants。[56] | 适合书签和嵌入，不能单独满足文件导入 |
| 公开 X HTML | 本例有 OG 及媒体实体。[1] | 本例有 3 MP4＋HLS。[56] | 本地 workerd 已通过 | 成功。[56] | schema 易变；平台抓取许可；云端出口未测 |
| 公开 syndication | 非本项目可依赖的官方 v2 契约 | 本次未取得 | 简单 HTTP 可调用 | 200 `{}`。[56] | 未继续构造客户端参数或变更身份 |
| 用户浏览器 / OpenCLI | 已登录会话的 Bookmarks/内部请求。[80][81] | 第一个 MP4 URL 实际可下；DOM 下载命令失败。[82] | 不能将整套程序直接搬入 | 1.8.6 真实分页通过；folder 404 | Chrome、扩展、本机进程、账号安全；不能消除平台条款 |
| yt-dlp 专用 X 路径 | 内部 API/guest/会话/可选 syndication。[38] | extractor 支持 variants | Python CLI 不等于 JS Worker 包 | 仅通用 extractor 测失败 | 登录/接口变化；HLS 时可能需要 ffmpeg |
| gallery-dl / Twikit / twitter-api-client | 内部 API/会话。[39][40][41] | 源码支持媒体 | 需要适配或外部进程 | 只读源码 | 许可、依赖、更新频率与账号风险 |

Workers 的 Node 兼容提供部分原生接口，但 `node:child_process` 列为非功能性 stub，不能据此运行桌面 Chrome、Python CLI 或系统 ffmpeg。[22]

## 5. 方案评分

以下保留**单链接视频搬运**维度的设计评分，不能衡量“我的书签”认证是否成立，也不决定最终采用顺序；不是成功率或基准测试。每项 1–5 分；权重为功能覆盖 25%、Worker 适配 25%、维护证据 20%、部署简度 15%、授权路径清晰度 15%；总分为 `Σ(单项分/5×权重)`。

| 方案 | 功能 | Worker | 维护 | 部署 | 授权路径 | 总分 / 100 | 硬门槛 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 官方 API＋Worker | 3 | 5 | 5 | 4 | 4 | 84 | 取得应用访问及相应保存许可，再用本例实测 |
| 公开 HTML＋Worker | 5 | 5 | 2 | 5 | 1 | 76 | 抓取许可未核实；不能因技术分高默认启用 |
| yt-dlp 辅助进程 | 4 | 1 | 5 | 3 | 2 | 60 | 授权路径和本例专用 extractor 未验证 |
| gallery-dl 辅助进程 | 4 | 1 | 4 | 3 | 2 | 56 | 会话依赖、GPL 分发义务、与视频 MVP 重叠 |
| OpenCLI 本机桥 | 4 | 1 | 4 | 2 | 2 | 53 | 书签认证已过；须禁用原版 DOM 下载与指纹补丁、限制设备权限 |
| Twikit | 3 | 1 | 2 | 2 | 1 | 37 | 登录链及缓冲下载需改造 |
| twitter-api-client | 3 | 1 | 1 | 2 | 1 | 33 | 近期维护、安全默认值不足 |

oEmbed 单独不评分：它满足书签路径，却缺少文件导入这一硬要求，不能与完整下载方案作同口径排名。[8][56]

认证 Gate 改变最终排序：**本机 OpenCLI Connector＋Cloudflare 是当前优先路线，因为已经读取真实 Bookmarks；官方 OAuth 保留为纯云路线，须先取得真实 grant 再决定。**[81][82] 公开 HTML 只作获准单链接适配器；任何方案遇到 DRM、付费、受保护内容或 challenge 都停止相应导入，分数不能覆盖硬约束。

## 6. 最小混合架构选择

| 实际阻碍 | 最小新增组件 | 仍留在 Worker 的职责 | 降级结果 |
| --- | --- | --- | --- |
| 正常公开页面必须借助用户浏览器才能读取，且访问/保存获得允许 | 用户本机 OpenCLI 或更窄的浏览器桥 | 任务、许可检查、存储、分类、播放鉴权 | 用户手动打开来源；无法合法获取则只留书签 |
| 合法媒体只能从该会话下载 | 同一个本机任务进程把字节上传到本项目 | 受限上传接口、哈希、配额、提交 | 不把 cookie 发送给云端 |
| 只有允许处理的 HLS、分离音视频或不兼容编码 | 一个临时任务进程，按需带 yt-dlp＋ffprobe/ffmpeg | 任务领取、成果验证和 R2 管理 | 保留原文件/来源；人工处理 |
| 内容受保护、付费或出现 challenge | 不新增绕过组件 | 记录原因、停止重试 | 链接或用户合法取得的本地文件 |

同一个受限进程可以同时承担必要的媒体工具，不为解析、下载、合流分别部署服务。ffmpeg 的许可证取决于构建选项和组合组件，选定镜像后还需核查具体构建。[50]
