# 04｜产品体验与信息架构

本篇是待实施的产品设计。所有容量、交互时延和默认值均为设计目标；没有完成前端开发或可用性测试。

产品成立的前提是 07 的认证 Gate。主要收藏入口改为“本机在线时同步自己的 X Bookmarks”；原版单帖 download 的伪成功问题见 08，界面必须以文件验证结果显示保存状态。[81][82]

## 1. 如何对标 Eagle

Eagle 的官方产品页将使用过程分为 Collect、Organize、Search、Browse，并列出标签、文件夹、智能文件夹、星级、重复文件处理和悬停预览。[14]

| Eagle 已描述的能力 | snail 的视频场景设计 | MVP 边界 |
| --- | --- | --- |
| 浏览器收集及批量整理。[14] | 同步自己的 X 书签、粘贴链接、拖入本地文件；收件箱统一接收 | 授权本机在线时的有限书签窗口；本地一次最多 20 个文件 |
| 标签、层级文件夹、星级。[14] | 文件夹表示项目/主题，标签跨文件夹，星级用于精选 | 支持手动整理和批量操作 |
| 智能文件夹。[14] | 保存“未分类＋来源 X＋小于 30 秒”等筛选条件 | P1；MVP 先保存最近筛选状态 |
| 扫描并合并重复文件。[14] | 同源去重和 SHA-256 完全相同文件去重 | 不判断画面相似、不合并不同码率视频 |
| 悬停播放视频与音频。[14] | 网格中只允许一个卡片静音预览；移开暂停 | 无自动有声播放 |
| YouTube/Vimeo 视频链接书签及预览。[14] | X 书签与已下载视频在卡片上明确标识 | 书签不伪装成本地媒体 |

核心体验是收藏之后容易再找到。视频播放器只是其中一个环节。

## 2. 信息架构

```text
资料库
├── 收件箱：刚加入、尚未整理的条目
├── 全部视频：具有媒体文件的条目
├── 链接收藏：仅保存来源的条目
├── 收藏精选：用户标星的条目
├── 文件夹：层级目录；一个条目可以属于多个文件夹
├── 标签：平铺标签、数量和重命名
├── 导入任务：排队、进行中、待处理、失败
└── 回收站：普通删除可恢复；权利撤回不进入普通恢复流程

条目详情
├── 播放器或来源链接卡片
├── 标题、笔记、标签、文件夹、星级
├── 来源作者、帖子地址、采集时间
└── 清晰度、时长、大小、文件可用状态

设置
├── 本机连接：配对、上次书签同步、离线、待重登、撤销设备
├── 已用容量、每日导入额度
├── 外部服务访问方式与许可状态
└── 导出资料目录、删除资料库
```

主视图采用左侧导航、中间卡片网格、右侧详情栏。窄屏将详情改为单独页面，筛选器折叠。使用键盘可以聚焦卡片、打开详情、暂停播放和关闭详情；删除动作提供可理解的结果与恢复入口。

“未分类”定义为不属于任何手动文件夹；“无标签”另设筛选，二者不混用。默认显示最近添加的条目，排序可以切换为标题、来源发布时间、时长、文件大小或星级。

## 3. 上传流程

1. 用户选择或拖入文件，界面显示名称、声明大小及待上传状态。
2. 服务端校验账号、额度和声明类型后创建上传任务；前端显示是否超出单文件或资料库配额。
3. 浏览器按 8 MiB 分片上传，默认同时传一个文件的两个分片；服务端保留已接收分片清单。
4. 所有分片接收后进入“校验文件”；该状态独立于“上传 100%”。
5. 服务端完成合并、大小检查、SHA-256、去重和发布引用；客户端可生成封面，但其媒体属性仍标记为客户端提供。
6. 成功条目进入收件箱；失败条目保留可操作的原因，不丢失已填写的标题、标签和笔记。

MVP 建议单文件上限 512 MiB、单批 20 文件、单库 100 GB。首先支持能在目标浏览器播放的 MP4；WebM、MOV 等可作为后续兼容范围，不承诺只靠扩展名就能播放。

对于容器可识别但浏览器不能播放的文件，显示“文件已保存，当前浏览器无法预览”，保留下载原文件入口；不把它显示为校验失败，也不自动付费转码。未知或伪装格式不进入可播放状态。

## 4. X 链接收藏流程

### 我的 X 书签（主要入口）

1. 用户登录 Snail，配对自己的本机 Connector，确认读取窗口和是否开启本机在线时轮询。
2. 首次只同步最近 N 条的规范化来源卡片；界面显示“已读取 N 条”“仍有历史未读取”，不宣称完成全库归档。
3. 新增来源进入收件箱；同源重复只更新观察时间，不覆盖用户笔记或重复占用存储。
4. 有权保存的具体媒体经批准才创建文件任务；其他书签保留允许的链接。
5. 本机离线显示最后成功同步时间；X 需要重登时让用户在自己的浏览器正常处理，不提示上传 cookie。
6. X 文件夹读取此次 404，MVP 不显示“已同步文件夹”；Snail 自己的文件夹/标签独立维护。[81]

### 单链接（补充及降级入口）

1. 粘贴链接，去除不参与标识的查询参数，解析帖子 ID。
2. 如果该帖已在当前资料库，直接打开已有条目或补充文件，避免新建重复收藏。
3. 展示来源、可取得的标题/作者以及访问结果；用户选择“保存链接”或在许可允许时“保存视频”。
4. 保存链接立即得到可分类的条目；保存视频另外创建后台任务，页面可以关闭。
5. 多视频帖按媒体项创建条目并保留同一来源分组，不将引用帖、推荐内容或整条讨论串自动导入。
6. 成功后切换为“文件已保存”；失败时仍保留来源卡片和整理信息。

本例的 oEmbed 提供作者及嵌入 HTML，而媒体变体实际来自页面状态；产品应允许“书签成功、文件导入未完成”的组合结果。[1][2][56]

### 用户能看到的状态

| 内部结果 | 卡片/任务文案 | 可操作项 |
| --- | --- | --- |
| `bookmark_only` | 已保存链接 | 打开原帖、添加本地文件 |
| `queued` | 等待导入 | 取消 |
| `resolving` | 正在读取来源 | 取消 |
| `fetching` | 正在保存视频，已接收 N MB | 取消；已知总长时才显示百分比 |
| `verifying` | 文件已接收，正在校验 | 等待 |
| `ready` | 文件已保存 | 播放、下载、整理 |
| `duplicate` | 已有相同文件 | 打开已有条目、保留独立笔记 |
| `needs_user_action` | 此来源需要人工处理 | 打开原帖、上传有权保存的文件 |
| `blocked_policy` | 此来源暂不支持保存文件 | 保留链接 |
| `source_unavailable` | 来源当前不可用 | 查看上次信息、按策略重试 |
| `failed` | 导入失败：可理解的原因 | 重试或保留链接 |

技术错误码、GraphQL 操作名、cookie 名称和上游响应体只出现在脱敏诊断界面，不进入普通产品流程。受保护或付费内容的失败界面不引导用户导出会话或绕过权限。

## 5. 浏览与播放

- 网格默认只请求缩略图；显示时长、来源和保存状态，避免同时预加载整屏视频。
- 指针稳定悬停约 400 ms 才启动静音预览，离开立即暂停；触屏使用明确的播放按钮。
- 详情播放器提供播放/暂停、拖动时间轴、音量、倍速、全屏和浏览器原生画中画能力检查。
- 播放 URL 指向自己的鉴权接口，Range 请求也要检查资料库权限，不直接暴露临时上游 URL。
- 原帖入口始终可找到；用户修改的标题与抓取的来源正文分别保存。
- P1 可增加视频时间点笔记；MVP 只做条目级笔记，不引入时间轴编辑器。

本例 MP4 的 `moov` 位于文件起始附近，首尾 Range 均成功，适合作为原文件播放的验证样本；这不是其他上传文件也具有相同布局的保证。[56]

## 6. 分类、标签与搜索

| 维度 | 行为 |
| --- | --- |
| 文件夹 | 支持父子关系、拖动移动；删除文件夹默认只移除分类，不删除媒体 |
| 标签 | 去首尾空格、Unicode 规范化；同库标签名称按规范化值唯一；重命名和合并均预览影响数量 |
| 批量操作 | 多选后添加/移除标签、放入文件夹、调整星级、移入回收站；禁止含糊的全库批量删除 |
| 关键词 | 搜索用户标题、笔记、来源作者和来源文字；不声称能搜索视频画面或声音 |
| 筛选 | 来源、文件/书签、文件夹、标签、星级、时长、尺寸、日期、是否缺失封面 |
| 组合逻辑 | 不同维度 AND；同一维度多选 OR；多标签默认全部匹配，并显示逻辑 |
| 空结果 | 保留筛选条件，提供“清空筛选”；不自动修改用户查询 |

D1 支持 FTS5，但 SQLite 默认 tokenizer 与 trigram 的行为不同；trigram 对短于三个字符的全文查询有限制，不能用“开了 FTS”承诺中文检索质量。[30][31]

MVP 对中文采用参数化包含匹配，先用资料库、状态和分类条件缩小集合；1 万条以内作为初始目标，查询延迟需实测。规模扩大后，以真实中文查询集比较 trigram、显式分词或专用检索方案，避免先引入向量数据库。

## 7. 删除、恢复和资料导出

普通删除立即隐藏条目，30 天回收期后回收无引用二进制；恢复时保留原文件夹和标签，已删除的文件夹不自动重建。

版权撤回、用户撤销保存授权或平台有效删除通知采用另一条流程：立即停止读取与分享，按适用义务清除来源内容和对应对象，不提供普通回收站恢复。X 的离线保存政策要求响应内容删除/修改及有关请求，不能把“永久收藏”作为产品承诺。[12]

MVP 的资料目录导出包含用户标题、笔记、标签、文件关系及来源 URL；X 内容批量再分发需要单独许可判断，不能把可导出元数据误做成公开数据集。[12][13]
