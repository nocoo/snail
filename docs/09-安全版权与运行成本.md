# 09｜安全、版权与运行成本

本篇保留安全设计和已有费用模型，认证 Gate 通过前不继续扩写成本或据此推动产品开发。主决策见 [07](07-X登录与认证可行性.md) 与 [08](08-OpenCLI登录桥与开源下载器源码研究.md)。没有配置线上权限、购买 API 额度或产生云端部署；价格为 2026-09-12 的公开文档快照，估算不等于实际账单。

## 1. 信任边界

不可信输入包括用户 URL、文件名、上传内容、上游 HTML/JSON、媒体清单、重定向和辅助进程回报。可信信息包括经过应用身份核验的资料库归属、服务器计算的完整摘要、数据库约束和经过校验的 R2 对象状态。

前端只保存条目数据和进度，不持有 X API 凭据或全桶凭据；会话从应用身份系统取得，不把“用户已在 X 登录”当作应用登录。

## 2. SSRF 与下载边界

OWASP 建议采用明确 allowlist、处理 IP/域名校验和重定向风险；仅在请求前做一次字符串检查不足以安全接收任意 URL。[32]

| 边界 | 设计规则 |
| --- | --- |
| 用户链接 | 只收支持的 X/twitter 状态链接；使用 URL parser；只允许 HTTPS 和默认 443 端口 |
| 规范化 | 提取帖子 ID 后重新构造目标 URL，不把原始输入直接交给 fetch 或 shell |
| 元数据主机 | 精确允许 `api.x.com`、`x.com`、`publish.x.com`；兼容域名先规范化；不是 `*.com` 或字符串 includes |
| 媒体主机 | 本阶段精确允许 `video.twimg.com` 和 `pbs.twimg.com`；新增 CDN 域名须有来源证据和回归检查 |
| host 欺骗 | 拒绝用户信息段、IP literal、非标准端口、换行、反斜线混淆、相似域名、尾随异常点、嵌套 URL 绕行 |
| 重定向 | `redirect: manual`，至多 3 跳，每跳重新解析和校验；禁止降级 HTTP |
| 凭据 | 官方 API Authorization 只用于对应 API origin；从不跟随重定向传给 CDN；CDN 默认无 Cookie |
| DNS | 不支持任意用户域名；不声称独立 DNS 检查后再 fetch 就已经钉住同一 IP；混合进程需拦截私网、回环、链路本地及重新解析风险 |
| 清单 | 每个 HLS 子清单、初始化片段和片段都重新过 allowlist；拒绝 `file:`、`data:`、任意本地路径等引用 |
| 媒体 | 限实际接收字节、总时间和无进度时间；先检查 MIME 和文件签名；拒绝把 200 HTML 写成视频 |

输入测试应覆盖 `x.com.evil.example`、`x.com@127.0.0.1`、localhost、IPv4/IPv6 回环、云元数据地址以及跨域重定向等恶意构造；测试只验证本地拒绝逻辑，不向内网探测。

本例媒体请求不需要身份、Referer 或额外签名计算即可返回内容，因而没有理由把本机浏览器会话送给媒体 CDN。[56]

允许任意站点的“通用下载器 API”不在 MVP。通用工具只可接收服务器已校验、与具体任务绑定的输入；不开放任意 extractor、命令参数、输出路径或下载协议。

## 3. 上传、内容和播放安全

- 分片每次最多 8 MiB，实际读取超限立即取消；总长度受 session 与资料库预留额度约束。
- 文件扩展名、Content-Type 和客户端哈希都不可信；检查文件签名并计算服务器完整 SHA-256，编码兼容性单独标记。
- 缩略图仅收经过检查的 JPEG/PNG/WebP，拒绝 HTML/SVG 等主动内容，默认 `X-Content-Type-Options: nosniff`。
- R2 key 只由服务器构造；原始文件名不能成为磁盘路径、对象路径或 shell 片段。
- 播放、HEAD、Range、下载和封面都检查当前用户及条目可见引用；猜到 blob ID 也不能读取。
- 普通用户不能指定任意 `library_id`、R2 key、multipart ID 或另一个任务的 ETag。
- oEmbed HTML 不直接放入 `innerHTML`；MVP 使用自己的来源卡片。如果以后启用官方嵌入，需要隔离渲染、CSP 和显式加载策略。
- X 正文、作者名和辅助进程 stdout 均作为数据处理；不把其中的“指令”用于控制任务。

R2 的 CORS 负责浏览器跨域读取规则，预签名 URL 负责临时授权；CORS 不能替代所有权检查，也不能阻止非浏览器调用者。[26][27]

为简化 MVP，媒体读取使用同源 Worker 和 `private, no-store`，不引入公共 CDN 缓存；后续要缓存时必须先证明用户隔离、Range 缓存键和权利撤回行为正确。

## 4. 凭据与辅助进程

X 官方凭据由服务端 secret 管理，不出现在 Vite 的客户端环境变量、源代码、文档或日志。临时媒体 URL 如果包含敏感查询参数，日志只留 host、路径摘要、采集时间和状态。

OpenCLI 源码可能导出浏览器 cookie 给 yt-dlp，下载辅助函数还可能自动读 Chrome cookie；安装版还存在整页媒体收集及 HTML 伪装 MP4 的实测失败，因此不能把该默认行为照搬成云端服务或可靠下载 API。[37][80][82]

当前推荐模式是用户已授权的本机 Connector 使用正常 Chrome 会话；云端只接收规范化 metadata 或受限上传流。未来 wrapper 必须关闭默认指纹补丁、自动 cookie 发现、个人下载器配置、插件和自动更新；缺会话时报告缺失，不扫描其他浏览器目录。设备配对、scope、凭据存储及撤销以 07/08 为准，不能把本轮原版 CLI 的默认行为说成已满足这些目标。

若后续运行 ffmpeg，先把已允许的输入下载到受限临时目录，再处理本地文件；不能让远程 HLS 清单未经校验地驱动 ffmpeg 请求任意网络地址或本地文件。

辅助进程使用非特权身份、独立临时目录和资源上限；任务完成即清理。固定依赖和镜像版本，核查分发许可证及第三方依赖，而不是在每个任务启动时拉取最新代码。[38][39][50]

## 5. 版权、平台条款与访问许可

### 已发现的外部要求

1. X 当前条款明确限制未经事先书面许可的 scraping，并要求通过其提供的公开接口及适用条件访问；不能通过改 UA、换身份或移到浏览器执行就认为消除了该限制。[13]
2. X 开发者政策要求离线保存内容随来源删除/修改而调整，并要求对 X 或相关账号所有者的有关要求尽快处理，通常不得晚于收到请求后的 24 小时；不能将其误写成“任何内容都可以保留到收到通知才处理”。[12]
3. X 开发者政策限制向第三方再分发 X 内容；具有 API 访问权不自动获得公开镜像或视频再分发权。[12]
4. 开源下载工具的许可证约束工具代码的使用与分发，不提供被下载视频的版权许可。[37][38][39][40][41]

### 产品处理原则

| 内容/条件 | MVP 的处理 |
| --- | --- |
| 用户自己的原始视频，或有明确保存许可的文件 | 允许上传并保存其权利依据 |
| 公开 X 链接，尚未确认文件复制许可 | 保存规范化链接和允许取得的元数据；不启用自动复制 |
| 有官方 API 访问且相应保存/展示条件明确 | 开启限定导入路径；保留来源和授权方式 |
| 获准通过公开页面解析的来源 | 可启用窄 HTML 适配器，但仍需云端可靠性验收 |
| 私密/受保护、付费、DRM、challenge | 停止文件导入；不尝试绕过 |
| 收到有效删除/版权要求 | 立即停读，清除对应来源内容，处理 R2/缓存/备份中的适用副本 |
| 来源状态无法确认 | 标记待核验；达到既定合规时限后停止展示有关来源内容，不无限期展示旧快照 |

界面上的“我有权保存”不是对平台许可的替代；服务器还需要明确 `access_basis`。`rights_basis` 记录 own/license/permission/unknown 等依据及必要备注，不收集多余个人信息。

本次研究没有确认示例账号是视频版权人，也没有获得许可证明。实验使用公开返回的媒体做短暂字节测量，没有触碰非公开内容或分发视频；技术成功与法律授权仍分开记录。[56]

MVP 默认没有公开视频库或分享链接。未来增加分享、商业化或 API 输出之前，重新确认平台合同、内容权利、删除机制及适用地区要求。

## 6. 应用配额与限流建议

这些是初始应用策略，可以在实际负载下调整；它们不是平台官方限制。

| 项目 | 初始值 | 达上限后的动作 |
| --- | --- | --- |
| 单文件 | 512 MiB | 413/任务限额错误，不继续接收 |
| 上传 part | 8 MiB，末片例外 | 超过实际字节即断开 |
| 单库容量 | 100 GB | 预留容量不足则拒绝新任务，仍允许读取/删除 |
| 每用户新建 X 文件导入 | 20 条/UTC 日，10 次/分钟 burst | 429，提供下次可用时间 |
| 每库每日新增接收字节 | 2 GB | 拒绝超额接收，防止依靠很多小任务绕过 |
| 同库活动下载 / 全局 queue 并发 | 1 / 2 | 排队 |
| 浏览器上传并发 | 单文件 2 parts；默认一次处理 1 个文件 | 排队，避免后台大量并发 |
| 上游解析输入 | 2 MiB | 拒绝超大页面，书签降级 |
| 元数据总超时 / 媒体无进度超时 | 15 秒 / 30 秒 | 取消请求并按错误类型退避 |
| 单次导入 wall time | 10 分钟 | 停止或交给明确允许的辅助路径 |
| 总尝试次数 | 最多 3 次 | 转失败，不无界重试 |
| 下载器 stdout/错误 | 有界读取并脱敏 | 截断，禁止填满磁盘或日志 |
| 上游失败熔断 | 连续 5 次同类 401/403/challenge | 暂停该路径；需要修复前置条件 |
| 费用告警 | 月预算 80% 告警，100% 停止新增可计费导入 | 保留上传/读取能力，按合规策略处理不能刷新来源的条目 |

限制按用户、资料库、来源提供方分别实施，不能只依赖浏览器按钮防重复。D1 条件更新实现配额预留和领取；不要用 Worker isolate 的全局变量作为全局限流器。[47]

## 7. 已核实的平台价格

货币为 USD；R2 的 GB、MiB 等单位按相应文档和本节公式区分。以下只列本方案可能使用的服务。

| 服务 | 查询到的公开价格 / 包含量 |
| --- | --- |
| R2 Standard | 存储 $0.015/GB-month；Class A $4.50/百万；Class B $0.36/百万；到互联网的 R2 egress 免费。[33] |
| R2 Standard 免费量 | 每月 10 GB-month、100 万 A、1000 万 B；不适用于 Infrequent Access。[33] |
| R2 计费进位 | 按计费单位向上取整；例如多于 100 万一次的操作量可能进位到下一百万单位。[33] |
| R2 Infrequent Access | $0.01/GB-month，但有 $0.01/GB 读取处理费、不同操作价格和 30 天最低保存期。[33] |
| Workers Paid | 账号最低 $5/月；含 1000 万请求和 3000 万 CPU ms，超出分别 $0.30/百万请求、$0.02/百万 CPU ms。[34] |
| 静态资源 | Workers 静态资源请求按文档不作为普通动态请求收费；路由设计应避免静态资源无谓进入业务 handler。[34] |
| Queues Paid | 每月含 100 万标准操作，超出 $0.40/百万；通常一次消息投递包含写、读、删三次操作，重试增加操作。[36] |
| D1 Paid | 含每月 250 亿行读取、5000 万行写入、5 GB 存储；超出 $0.001/百万读取、$1/百万写入、$0.75/GB-month。[35] |
| X API | 当前公开页是按使用量预购 credits，而非固定月订阅；Post Read $0.005/资源，User Read $0.010/资源。[11] |

R2 免流量费不意味着整个应用免费：Worker、操作数、数据库、身份服务、域名、辅助进程和 X API 都有自己的成本。频繁拖动播放进度会产生多个 Range/鉴权请求，不能按“一次播放等于一次读取”估算。[17][33][34]

D1 读取按扫描行而不是返回行计量，索引更新也影响写入；关键词全表扫描和过细的进度更新需要通过真实 `rows_read/rows_written` 观测控制。[35]

## 8. 可重算的成本模型

对 R2 Standard，令 `G` 为月度计费口径下的存储 GB-month，`A/B` 为当月操作数，则按当前免费量和进位规则估算：[33]

```text
R2 ≈ ceil(max(0, G - 10)) × 0.015
   + ceil(max(0, A - 1,000,000) / 1,000,000) × 4.50
   + ceil(max(0, B - 10,000,000) / 1,000,000) × 0.36

Workers ≈ 5
        + max(0, 动态请求 - 10,000,000) / 1,000,000 × 0.30
        + max(0, CPU毫秒 - 30,000,000) / 1,000,000 × 0.02

Queues ≈ max(0, 操作数 - 1,000,000) / 1,000,000 × 0.40
```

R2 存储使用月内每日峰值的平均口径，不能只用月末一个 list 结果代替实际计费量。[33]

### 两个设计场景

假设平均视频 50 MB（十进制），封面 0.2 MB；无重复副本，整月维持相应存量，D1 小于 5 GB。下列请求和 CPU 数均是假设输入，没有云端测量；中等场景需要多个资料库或提高初始容量上限。

| 场景 | 存量 | R2 A / B | Worker 动态请求 / CPU | 估算 R2 | Cloudflare 基线合计 |
| --- | --- | --- | --- | ---: | ---: |
| 个人 | 1000 条，50.2 GB | 5000 / 60 万 | 30 万 / 200 万 ms | $0.615，约 $0.62 | 约 $5.62/月 |
| 较大资料库 | 10000 条，502 GB | 5 万 / 600 万 | 300 万 / 2000 万 ms | $7.38 | 约 $12.38/月 |

上表假设 Queue 和 D1 操作仍在包含量内，未计税费、域名、身份服务、备份、辅助进程或 X API。若同账号其他应用已用完免费量或包含量，需要按全账号用量重算。[33][34][35][36]

### X API 可能比存储更贵

以下是既有的普通 Post Read 条件估算，不适用于所有 Bookmarks 请求。自有 developer app 读取同一所有者书签可能符合 $0.001/资源的 Owned Reads；精确条件与官方授权 Gate 见 07。[11] 当前主方案是本机 Connector，未发生这里估算的 API 账单。

按当前 Post Read 单价，300 个计费帖子资源约 $1.50，3000 个约 $15；如果同时取得计费的作者资源，还需按实际 User Read 数加算，不把 expansions 的最终账单当作已经验证。[11]

X 文档描述同一 UTC 日内资源重复读取通常去重收费，但同时注明这是 soft guarantee；本模型不把它当硬性预算保障。[11]

例如为了来源更新，每天重新检查 1000 个帖子、持续 30 天，仅帖子读取就可能是 `1000×30×0.005 = $150/月`，还不含作者读取。这是条件成本推算，不是本次实际支出；也不能因为成本高就忽略适用的删除/更新义务。[11][12]

因此要在开启 X 自动复制前确定内容同步方式、API 计费资源、更新频率和月预算。预算不足时关闭新的自动复制，并停止展示不能按策略确认状态的 X 内容；不能改用未经允许的抓取来规避费用。

## 9. 需要观测的运行指标

任务成功率分为“允许且可访问样本中的文件导入成功率”“仅书签成功率”和“策略阻断数”；不把受保护或未获许可内容算作下载器可靠性失败。

最少记录：各阶段耗时、来源 401/403/429/challenge 比例、平均接收字节、R2 写入失败率、完整性失败、重复节省字节、队列等待、孤儿对象数量、Worker CPU、D1 扫描行及每提供方花费。

发布前用相同方法测真实云端结果；本次没有以上生产指标或实际账单，不能把估算当作基准。
